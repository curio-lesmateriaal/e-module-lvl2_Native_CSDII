Je gaat geen code schrijven, maar een API **ontwerpen**: welke endpoints en HTTP-methoden heb je nodig?

## Opdracht — Bibliotheek-API

Stel je bouwt een API voor een bibliotheek die boeken (`Book`) beheert. Maak een routetabel zoals die uit de theorie:

| Methode | Route / Endpoint | Beschrijving |
|---|---|---|
| ? | ? | alle boeken ophalen |
| ? | ? | één boek ophalen op id |
| ? | ? | een nieuw boek toevoegen |
| ? | ? | een boek verwijderen |
| ? | ? | de gegevens van een boek wijzigen |

Vul de methode (GET/POST/PUT/DELETE) en de route in. Bedenk daarna zelf **twee extra endpoints** die handig zouden zijn (bijv. zoeken op auteur, alleen beschikbare boeken) en zet ze erbij.

## Vragen

1. Waarom heeft een POST wél een request body en een GET niet?
2. Twee routes hebben dezelfde URL `/books` maar een andere methode. Hoe weet de server dan wat hij moet doen?
3. Wat hoort de server terug te geven als je `GET /books/9999` doet en boek 9999 niet bestaat?
